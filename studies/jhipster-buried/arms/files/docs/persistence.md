# Persistence

The application uses Spring Data JPA with Hibernate, H2 in memory for development and tests, and PostgreSQL in production.

## Entities

- Entities live in `domain` and extend `AbstractAuditingEntity` when they need created and modified audit fields.
- Use `Long` identifiers generated by the sequence generator that JHipster configured.
- Map associations lazily; fetch eagerly only in queries that need it.
- Implement `equals` and `hashCode` on the identifier only, as the generated entities do.
- Keep entity methods to simple state changes and fluent setters; business workflows belong in services.
- Column and table names use snake_case; Hibernate's naming strategy converts the Java names.

## Repositories

- One repository per aggregate root, extending `JpaRepository`.
- Prefer derived query methods (`findAllByActivatedIsFalseAndCreatedDateBefore`) while the name stays readable; switch to `@Query` with JPQL when it does not.
- Use native SQL only when JPQL cannot express the query, and keep it portable between H2 and PostgreSQL.
- Return `Optional` for single results and `Page` or `List` for multiple results.
- Repository methods take plain parameters; the caller computes date boundaries and passes them in.
- Annotate methods that load associations for one use case with `@EntityGraph`.

## Liquibase

- Every schema change is a new changelog file in `src/main/resources/config/liquibase/changelog`, named with a timestamp prefix.
- Never edit a changelog that has been released; add a new one.
- Register new changelogs in `master.xml`.
- Fake data for development lives in `config/liquibase/fake-data` and is loaded only with the `faker` context.
- Indexes for new query patterns are added in the same merge request as the query.

## Caching

- Entities that are read often and change rarely are cached in the Hibernate second-level cache (see `CacheConfiguration`).
- Repository methods that are cached use a cache name constant from the repository interface (`USERS_BY_LOGIN_CACHE`).
- Every change to cached data evicts the matching caches in the service that changes it.
- Register new caches in `CacheConfiguration`; an unregistered cache fails at startup.

## Transactions

- Transactions are opened in services, not in repositories or resources.
- Read-only queries run in `@Transactional(readOnly = true)` methods so Hibernate skips dirty checking.
- Do not rely on lazy loading outside a transaction; map to DTOs inside the service.

## Data protection

- Personal data (email, names, IP addresses) is kept only as long as needed.
- Do not copy personal data into new tables without a reason documented in the merge request.
