# Plan 7 (n8n conventions) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A registered, piloted study `studies/n8n-conventions` that compares n8n's own written rules (as shipped) with the same rules as lint rules and the feedback loop, plus the analysis code and the OSF text `studies/plan-7.md`.

**Architecture:** A copy of the Plan 6 Formbricks study, adapted to n8n.
`plugin/conventions.mjs` holds each rule in the maintainers' words, with every instruction file and block it comes from; `plugin/index.js` turns each into one ESLint rule; `arms/rules.sh` removes the blocks, adds pointers and installs the codemyrules loop; `bench/plan7.mjs` runs H16 and H17 with the Plan 6 statistics.

**Tech Stack:** Node 24, ESLint 9.17.0, `@typescript-eslint/parser` 8.18.0, `vue-eslint-parser` 9.4.3, node:test, Docker (`node:24-bookworm`), pnpm (n8n's own), Claude Code.

## Review Focus

- A `.vue` file that breaks a rule must give a finding; a checker that cannot parse `.vue` silently finds nothing. Test: Task 4 invalid examples in `.vue`.
- `as const` and `as` in test files are allowed by the rule's own text and must not be flagged. Test: Task 3 valid examples.
- A rule block that appears in two files (`no-as-cast`, `no-any-in-nodes`) must be removed from both, and nothing else in any instruction file may change. Test: Task 6 arm test.
- The loop in the `rules` copy must actually lint: a missing `node_modules` link or a wrong config path makes it silent. Test: Task 6 runs the installed linter on a violating file.
- A run that edits an `.ee` file must be caught before publishing. Test: Task 1 `check-ee` test.

### Task 3: Checkers for the root rules

**Files:**
- Create: `studies/n8n-conventions/plugin/index.js`, `studies/n8n-conventions/eslint.config.mjs`
- Modify: `studies/n8n-conventions/plugin/conventions.mjs` (examples, `files`), `plugin/conventions.test.mjs` (per-rule tests as Formbricks)

**Interfaces:**
- Consumes: `conventions`, `TESTS` (Task 2).
- Produces: ESLint plugin `local` with rules `local/<id>`; `eslint.config.mjs` default export as Formbricks', with TypeScript files parsed by `@typescript-eslint/parser` and `.vue` by `vue-eslint-parser` (`parserOptions.parser` = the TS parser).

Scope (`files`) and what each rule reports:
- `repositories-compose`, files `packages/**/*.ts`: a class whose superclass is `BaseRepository` or `Repository` (also with type arguments) and that is exported or has a `Service` decorator. A non-exported, undecorated subclass is the allowed private table.
- `no-manager-in-business-logic`, files `packages/cli/src/**/*.ts`, ignores `**/repositories/**`, `**/database/**`, `**/migrations/**`, `**/*.repository.ts`: a member access `.manager`, or a call to `createQueryBuilder`.
- `no-as-cast`, files `packages/cli/src/**/*.ts`, `packages/frontend/editor-ui/src/**/*.{ts,vue}`, `packages/nodes-base/{nodes,credentials,utils}/**/*.ts`: a `TSAsExpression` whose type is not `const`. `TESTS` are ignored, as the rule allows `as` in test code.
- `shared-helpers`, files as `no-as-cast` but ignoring `packages/@n8n/utils/**`: a function or variable named `isRecord`, and the expression `typeof x === 'object' && x !== null && !Array.isArray(x)` (either order of the three parts).

- [ ] **Step 1: Write the examples** in `conventions.mjs` and the per-rule test loop in `conventions.test.mjs`. Required cases: `export class UserRepository extends Repository<User> {}` invalid; `class UserTable extends BaseRepository<User> {}` valid; `@Service() export class UserRepository { constructor(private readonly table: UserTable) {} }` valid; `this.repo.manager.transaction(...)` in `packages/cli/src/services/x.service.ts` invalid and in `packages/cli/src/databases/repositories/x.repository.ts` valid; `const a = b as string` invalid, `const a = [1] as const` valid, the same cast in `x.test.ts` valid; `const isRecord = (v: unknown) => ...` invalid in `packages/cli/src/x.ts` and valid in `packages/@n8n/utils/src/x.ts`.
- [ ] **Step 2: Run** `npm test`. Expected: the four rules FAIL (not defined).
- [ ] **Step 3: Implement** the four rules in `plugin/index.js` (Formbricks shape: `checks[id](report, context)`, message `rule` = prose) and `eslint.config.mjs`.
- [ ] **Step 4: Run** `npm test`. Expected: PASS.
- [ ] **Step 5: Commit** `git add studies/n8n-conventions && git commit -m "Plan 7: checkers for the root rules"`.
